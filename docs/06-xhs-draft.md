## 正文草稿

最近 Jev（TypeSafe 的 System One 决策模型）生态很热，我没有做又一个聊天 wrapper，而是拿它解决了一个具体问题：

交易所的充提风控——每笔充值/提现进来，该自动放行、转人工、还是直接冻结？

架构上最关键的一个决定：**模型只做分诊，裁判权留在代码里**。

🔹 黑名单/制裁地址？硬规则一票否决，根本不调模型
🔹 高风险提现只冻结不降级（广播出去就要不回来了）
🔹 高风险充值已经上链，转账户复查而不是冻结
🔹 模型超时/挂了？降级到人工，绝不自动放行

最意外的是校准实验的结果。我拿 100 条标注样本做了三列对照（真实 API 调用，不是 mock）：

| 方案 | 准确率 | 漏放 |
|---|---|---|
| 纯规则 | 68% | 0 |
| Jev 门控 | 50% | 0 |
| 组合 | 50% | 0 |

规则居然赢了——但这恰好证明了架构是对的：窄场景下模型会过度升级（65% 的单子被它送去人审），但它**一笔该冻的都没漏**。所以让它做分诊层兜底，而不是当裁判。

另外两个实测发现：
🔸 confidence 在这个场景不带排序信息（最高信度桶准确率反而最低）
🔸 Jev 自己给的 route 建议，和代码组合出的决策只有 72% 一致——那 28% 就是工程的价值

防 prompt 注入也做了：token 名字是攻击者可控的，所有外部字符串白名单清洗，10 条注入回归样本，没有一条注入改变了路由结果。
