> v2 改动依据 `docs/04-audit.md` §6：全文补证据档位；三处关键数字降级为未核验；生态卡位结论修正；把"不能当设计依据用"的条目显式标出。

## 0. 证据档位约定

全文每条外部宣称标一档：

- **[已核验]** 多个独立来源一致
- **[部分核验]** 单一来源，或来源间冲突，或多处复述但同源（典型：第三方转引厂商自报）
- **[未核验]** 检索零命中或来源不可达。**这是"我核不到"，不是"它不存在"。**

核验通道限制（2026-09-22 实测）：本环境出站抓取被白名单拦截，中文检索对中文实体零命中，英文检索是唯一有效通道。**所以全部中文来源（awesome-jev-zh、中文社区实测）一律 [未核验]。** 下游文档（PRD、开发计划）不得把 [未核验] 条目当既定事实继承。

## 1. Jev 是什么（一句话）

TypeSafe 的 System One 决策模型：输入一份 `state` + 一组带类型的问题，**一次前向**返回校准过的概率/选择/分数，不生成任何文本 [已核验]。2026-09-15 开放早期访问 [已核验]。延迟 70–500ms [部分核验：官方自报，多处第三方转引同源，非独立实测；另有一份第三方实测给 100–200ms]。本质是「一次前沿智能的函数调用」。

## 2. API 硬规格

| 项 | 值 | 档位 |
|---|---|---|
| 端点 | `POST https://api.typesafe.ai/v1/systemone`；无 `/v1/chat` 类端点 | [已核验] |
| 认证 | `Authorization: Bearer <key>` | [部分核验] |
| 模型 | `jev-latest`（当前 = `jev-1.13`），生产建议锁版本号 | [已核验] |
| 请求体 | `{model, state, questions}`；state 仅文本 | [部分核验] |
| 上下文 | 单请求 64k token；state + 最长问题 ≤ 32k | [未核验] |
| 三种原语 | `choice`（选项→描述，≤255 项）/ `score`（2-10 档有序）/ `noul`（是非，返 0-1 概率） | [已核验]（档数上限 [部分核验]） |
| 返回 | `answers.{name}` 含结果值 + `confidence` + `probabilities`；`usage.input_tokens`（输出免费） | [部分核验]（每问题各带 confidence 这一点 [已核验]） |
| 价格 | **$0.042 / 百万输入 token**，输出不计费 | [已核验]（官方文档 + 4 份第三方） |
| 限速机制 | 超限返 `429` 并带 `retry-after`；官方 SDK 默认遵循退避 | [已核验] |
| 限速数值 | 250k token/秒、1200 请求/分 | **[未核验]** |
| 同请求多问题 | 并行求值、彼此隔离（互相看不见对方答案） | [已核验] |
| 加问题不增延迟 | — | [未核验] |

两处必须自己闭合的缺口：

1. **限速数值未核到。** 若 1200 请求/分成立，硬顶就是 20 req/s——日 10 万笔均值 1.16 笔/秒看着宽裕，但充提峰值高度不均匀。**上线前去 console 看真实配额**，别照抄这张表。
2. **价格有一处冲突来源** 写 $0.42/M（差 10 倍），该站自称是官方 API 之上的托管层，非官方口径。取高值结论不变（见 §6）。

## 3. 语义关键：confidence 与校准

- `choice/score` 回答「是什么」，对应的 `confidence` 回答「要不要动手」——**门控必须同时看答案值与该问题的信度两个字段** [已核验：官方 use-case playbook 明确要求由调用方代码选阈值]。
- confidence 是分布的尖锐度，不是「这条一定对」；校准是群体统计性质，**阈值必须在自己的标注数据上重新量** [部分核验]。
- **`confidence` 是 per-question 返回的**，一次请求 4 个问题就有 4 个 confidence [已核验]。门控逻辑里不存在"那个 confidence"，必须写明取哪一个——这是 PRD §4.5 的硬约束来源。

**两条不能当设计依据用的传闻**（原 v1 当结论写，v2 降级）：

| 传闻 | 档位 | 为什么不能用 |
|---|---|---|
| confidence 偏饱和（大量 1.00），阈值别卡太高（称 n=15 中文社区样本） | **[未核验]** | 中文源核不到；且 n=15 本身不足以支撑阈值决策。**但这条指向的风险是真的**：若饱和成立，阈值扫描表会退化成没有区分度的表。→ 行动：**M1** 用自己 20 条探针实测饱和度，用自己的数据替掉它 |
| 攒批发送可能比逐条更准（同批样本互为参照） | **[未核验]** | 与已核验的"同请求多问题彼此隔离"存在语义张力，自相矛盾未解。别当依据 |

## 4. 能力毛边（→ 我们的设计约束）

| 毛边 | 档位 | 对 jev-guard 的约束 |
|---|---|---|
| 不擅长数字/计数/日期比较 | [部分核验] | **所有算术在代码里做**：金额分档、频次、速度先算好再喂文本 |
| 长而嘈杂的 state 准确率下降 | [部分核验] | state 只放结构化特征摘要，不塞原始 tx 全量 JSON；**空值字段一律不渲染** |
| state 内注入指令可干扰结果 | [部分核验] | 地址、token 符号、对手方标签等**外部可控字符串**必须转义+截断（PRD §4.4a，v1 漏掉了这条） |
| 字面理解，边界不进 criteria 就会错分 | [部分核验] | criteria 必须写清边界（金额档位、时间窗定义） |
| 窄任务上传统基线可能更准 | [部分核验]（方向本身被官方承认）；**具体数字"钓鱼邮件 Jev 62.6% vs 正则 91.8%" [未核验]** | **Jev 不做唯一裁判**：硬规则一票否决，Jev 做分诊层 |

最后一行是全文最需要注意的地方：**它支撑了整个架构的核心决策，但那个精确数字我核不到。** 处理办法是把论证换个支点——"窄任务上传统基线可能更强"这个方向官方自己承认，而"AI 不做资金类决策的唯一裁判"本身就是风控常识，不需要一个二手数字来证明。**README 里不要引用 62.6%/91.8%**，除非找到原文并注明测法。真正该做的是 §7 第 4 条说的：自己跑一个规则基线对照，用自己的数字说话。

## 5. 竞品/空位扫描（2026-09-22，发布第 7 天）

**已拥挤方向** [部分核验]：浏览器操作、上下文压缩、交易 bot、开源复刻、awesome 清单。具体量级（"全生态 1800+ 项目"、"jev-ultrafast 14k★"）**[未核验]**，不要写进 README。

**awesome 清单不是一两份，是 7 份以上** [已核验]：核到 kraayenjon、yibie、cobanov、ckaraca、hellogumbo、valentynkit、Anil-matcha 等同名/近名的竞争性列表，其中一份自己写着"用于发现，不代表背书"。→ 单份收录的价值被严重稀释，开发计划 §2 的 **M5** 投递策略据此改过。

**空位结论修正**（v1 写"0 个项目"，过于乐观）：充提风控 / AML 方向**未见直接命中** [部分核验]，但邻域已经有人：加密交易方向的 Jev 项目、安全运营（SOC）告警分诊方向的实现，以及一份 2026-09-20 专门 survey 金融/交易类 Jev 项目的调查。**即"无人做"的邻居已经到门口，且有人在系统性扫金融方向——这个空窗以天计。**

这不影响做，但改变两件事：一是要快（见开发计划 §5 风险表）；二是 README 的差异化不能泛泛说"Web3 风控"，必须说到**"充提链路 + 自建校准数据"**这个粒度，因为前者随时会被填上，后者别人没有。

## 6. 成本测算 [算术已自校验]

单次请求：state（结构化特征 ≈ 300 token）+ 4 个问题（≈ 200 token）≈ 500 输入 token。
500 × $0.042/1M = **$0.000021/笔**，日 10 万笔 ≈ **$2.1/天**。

即便按 §2 那处冲突来源的 $0.42/M 取高值，也是 $21/天。**"成本不是约束"这个结论对来源冲突稳健，可以放心写进 README。** 注意 token 估算本身是估算，实际数字在 **M1** 打通后用 `usage.input_tokens` 实测替换。

## 7. 关键设计结论（输入给 PRD）

1. **Jev 是「分诊层」不是「裁判」**：黑名单/制裁名单走硬规则一票否决；Jev 输出建议 + confidence，门控逻辑在 Java 代码里。依据：官方承认窄任务基线可能更强 [部分核验] + 资金类决策不交给单一概率模型（风控常识，不依赖外部数字）。
2. **问题原子化，组合逻辑自己写**：依据是官方 use-case playbook 原话"让你的代码组合答案、选阈值、执行授权" [已核验]。原 v1 引用的"实测值 32 个百分点" [未核验]，已从论证中移除——不需要它。
3. **特征代码化**：金额分档、24h 频次、速度全部 Java 侧预计算，文本化进 state。
4. **评测即卖点，但必须带对照组**：内置 labeled 样本 + 校准报告。**单独给 Jev 的准确率说明不了任何事**，必须并列纯规则基线——这既是唯一能量化"这层 AI 值不值"的办法，也是对 §4 最后一行那个核不到的数字的正面回应。
5. **诚实是差异化的一部分**：样本为合成+自标、硬规则数据源未接入、延迟为厂商自报——这些主动写进 README 的局限性章节，是 7 份 awesome 清单里的项目都不会写的东西。
6. **无 key 可跑**：Mock 模式返回 fixture 答案。但 **mock 模式下不得产出校准报告**（否则 clone 者会拿到一份准确率接近 100% 的假报告）。
